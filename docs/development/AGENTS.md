## 项目边界

- PostgreSQL 是正式课表唯一事实源。
- 飞书只接收单向同步，不反向覆盖数据库。
- AI 只能解析需求、生成草稿和解释候选，不能发布正式课表。
- 确定性规则引擎负责判断候选是否可行。
- 真实 CSV、生产数据、密钥和数据库备份不得提交到 Git。

## 修改规则

- 同一工作树同一时刻只能有一个 Writer。
- Scout、Reviewer 和 Researcher 默认只读。
- 开始修改前检查 `git status`，存在来源不明的改动时停止并上报。
- 遇到未确认的产品、领域、权限、费用、部署或架构决策时停止并交还主 Agent。
- 不顺手扩展任务范围，不引入当前任务不需要的依赖或抽象。
- 只有用户明确说“同步到 GitHub”时，才按同步规范执行远程合并和推送。

## 交接要求

Writer 完成后必须说明：

- 修改了哪些文件；
- 实现了什么；
- 明确未实现什么；
- 运行了哪些命令及其结果；
- 剩余风险；
- 需要用户或主 Agent 决定的问题。
